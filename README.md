# HW1

Весь pipeline выполняется в **[hw1_colab.ipynb](hw1_colab.ipynb)**.
Модель, четыре формулы, замеры, калибровка и графики записаны прямо в ячейках.
Импортов локальных файлов в ноутбуке нет. `models.py` и `equations.py` содержат
код для сдачи. `calibrate.py` отдельно подбирает параметры из `results/measurements.csv`.

## Запуск

Открыть ноутбук в Colab, выбрать GPU и выполнить ячейки сверху вниз.
Последняя ячейка скачает архив результатов. Распаковать его в `results/`.
Расчёты для переписывания от руки: **[derivations.md](derivations.md)**.

## Условия измерений

Tesla T4, PyTorch **2.11.0+cu128**, CUDA **12.8**.
Лимит памяти: `set_per_process_memory_fraction(0.25, 0)` — **3.641 GiB**.
FP32, eval, inference_mode; TF32 выключен, cudnn.benchmark=False.
Время — медиана 20 проходов после 5 прогревочных. Память — пик одного прохода.
Энергия всей GPU — интеграл мощности NVML за 3 секунды, делённый на число проходов.

## Результаты и обсуждение

В `results/measurements.csv` 132 конфигурации: 130 успешных и 2 OOM.
62 успешные базовые точки использованы для калибровки, 68 дополнительных — для проверки.
MAPE на проверке: время **24.50%**, память **38.08%**, энергия **33.38%**.
Графики: `results/figures`; параметры: `results/theta.json`.

FLOPs и память растут преимущественно как BS². На малых входах заметны накладные
расходы запуска; на больших — вычисления и обмен с памятью. Постоянные скорости
в формуле описывают общую зависимость, но не изменения алгоритмов cuDNN и
эффективности GPU. Формула памяти учитывает живущие одновременно тензоры;

OOM зарегистрирован при B=256, S=496 и S=512. Оценки памяти: 3.992 и 4.254 GiB.
Обе оценки выше лимита 3.641 GiB. Это опыт с ограничением 25% памяти T4.

Энергия измерена для всех 130 успешных конфигураций. Модель использует постоянный
коэффициент мощности; это приближение даёт ошибку 33.38% на проверке.
